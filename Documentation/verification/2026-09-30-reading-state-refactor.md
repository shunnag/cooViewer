# 読書状態・保存・EPUB セッションの整理

対象は `refactor/code-quality` の cooViewer。開始時点は `master` の `4308c06`。
全リポジトリの品質改善を追跡する Beads `cooViewer-a9qn` のうち、値型と一括保存
(`.1`/`.2`)および EPUB・合本の状態の整理(`.3`)の検証記録である。

## 値型と保存の境界

- フィット・補間の値を ReaderView から Core へ移し、CALayer のフィルタ変換は UI に残した。
- しおり・保存設定・リソース既定値を Core へ移し、Book からストア実装への依存を除いた。
- BookSource、PageEntry、BookSourceFactory、SortMode を責務に沿って配置した。
- 一冊の保存入力を ReadingStateSnapshot で表し、JSON の記録と更新は BookStateRecord、
  ファイルの読み書き・保護・復元は BookHistoryStore が担当する。
- 画像本・EPUB とも一回の保存で状態 JSON を一度だけ更新する。最近項目は別ファイルのまま。
  保存成否は実際の状態ファイル書込に従い、成功した場合だけ成功時刻を進める。

既存の rawValue、JSON キー、旧 UserDefaults のキーを維持した。読取不能・未知版を
一度観測した本への上書き抑止、保存時点の位置復元条件、実測の最大3件の MRU を保つ。
連続通知中の失敗再試行も30秒に制限し、失敗した保存を成功扱いしない。

## EPUB の所有者と寿命

EPUBReadingSession は提示する一冊を所有し、EPUBSearchSession はその本の検索を所有する。
表示ビュー・入力モニタ・提示 epoch・合本全体の状態はウインドウに残す。
旧セッションを保存して終了する処理を、EPUB 間切替と EPUB 退出で共通にした。
閉窓では一時処理だけを止め、Dock からの再表示に必要な読書内容を保持する。

検索・厳密着地・保存予約・脚注・遅延 UI クロージャは、開始時のセッションを照合する。
同じ publication を開き直して世代番号が同じ値になっても、旧結果を新状態へ反映しない。
検索、しおり、脚注の UI 配線と、純粋なしおり位置ロジックを機能別のファイルへ配置した。

GPT-6 Astra の読み取り専用レビューで、同じ URL を再提示した後の旧しおり編集シートが
ストアだけを更新し、次の保存で古い配列に戻る経路を検出した。ページ再計算の可否と、
確定編集を現在の同じ URL へ反映する条件を分けて修正した。
Controller のストアを注入できるようにし、実編集コールバックから後続保存・新規ストアの
読込までを、一時ディレクトリと隔離 UserDefaults で検証した。

## 合本の対応表とナビゲーション

CollectionPageMap は UI/Washi に依存しないページ対応の値として Core/Book へ移した。
構築は読書側の CollectionPageMapState が所有し、合本の往来と構築の配線を
ReaderWindowController+Collection にまとめた。サムネイルには表示とセル展開を残す。

構築の識別を文字列の folder#metrics から型付きキーと要求オブジェクトへ変更した。
同じ版面でもエントリ列が変われば新しく構築し、旧完了・旧取消が新要求を解除しない。
未完マップの予算は公開された結果だけで数え、ページ列の変更後へ持ち越さない。
完成済みの版面へ戻った場合は、別の版面の不要な構築を止める。

CollectionNavigationState は確定降格・一過性失敗を別の集合で所有する。一過性集合を
外部へ公開せず、着地時の消費以外にクリアする API を設けない。着地方向の消費と
失敗マーカーの保持を分け、個別 EPUB の終了で再入場防止の印を失わないようにした。

追加7件は、並べ替え中の構築切替、同じキーの再構築へ遅れた結果が戻る場合、
未完結果の予算、閉窓後の構築再開、二種類の失敗記録、解析失敗の完了順を検証する。
最後の検査では最初の巻の準備を停止し、後発の巻を先に表紙へ着地させ、その後に
最初の巻の失敗を完了させた。成功時だけでなく失敗時も提示 epoch を照合する修正により、
最新の着地ページを保持する。

## 保存処理の計測

`Scripts/bench/book-state.swift` が本番の BookHistoryStore と値型を直接リンクする。
20しおり・100項目の実測を含む EPUB 状態を200回保存し、順次4回の API 呼出しと
一括保存を6巡交互に測った。各巡は独立した一時保存先と隔離 UserDefaults を使う。

| 200回の保存 | 状態 JSON 書込 | 中央値 | 最小–最大 |
|---|---:|---:|---:|
| API を順次4回呼ぶ | 800回 | 293.606 ms | 290.062–329.123 ms |
| 一冊のスナップショット | 200回 | 81.803 ms | 78.829–84.901 ms |

処理時間の中央値は約72%減少した。最後に別ストアでディスクから読み直した位置・しおり・
実測が一致した。ログは `book-state-bench.txt`。
この値は保存経路だけの計測であり、ページ描画や書庫展開、アプリ全体の速度を表さない。
